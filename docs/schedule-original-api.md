# 원본 근무표와 주당 근무 시간 API

형제 저장소 `library-dashboard-backend`의 `src/main/java/dev/library/Api.java`에 아래 API를 구현하고 프론트에서 연결했다. 기존 `/api/schedule`과 `shifts`는 실제 근무표 관리에 유지한다. 모든 경로 앞에는 `/library-dashboard/api`가 붙는다. 백엔드 재시작·배포 시 `V2__original_schedule.sql` 마이그레이션 적용이 필요하다. 테스트·빌드·DB 마이그레이션 실행은 생략했다.

## 저장 기준

- 실제 근무표: 기존 `shifts`. 근무 변경 요청을 반영하면 이 데이터만 바뀐다.
- 원본 근무표: 해당 주에 합의한 근무표의 독립적인 스냅샷. 실제 근무표 수정·삭제·주 복사로 바꾸지 않는다.
- 주당 근무 시간: 원본에서 자동 계산하되 근무자별 조정값이 있으면 그 값을 사용한다. 실제 근무표와 원본 근무표 어느 쪽도 조정값 저장으로 바꾸지 않는다.
- 원본을 다시 저장하면 조정하지 않은 사람의 수치는 새 원본을 따른다. 기존 수동 조정값은 유지하고, 사용자가 조정을 삭제하면 새 원본 계산값으로 돌아간다.
- 주 키는 한국 시간 기준 월요일의 `YYYY-MM-DD` 문자열이다. 주별로 원본과 조정값을 각각 보관한다.

## DB 변경

기존 Flyway 파일을 고치지 말고 다음 빈 버전에 새 migration을 추가한다. 로컬 H2와 운영 PostgreSQL 양쪽에서 사용할 수 있는 타입·제약조건을 사용한다.

| 테이블 | 필드와 제약조건 |
| --- | --- |
| `original_schedule_weeks` | `week` 기본키, `updated_by` → users, `updated_at`. 저장되지 않은 주와 저장된 빈 원본을 구분한다. |
| `original_shifts` | 자체 `id`, `week` → original_schedule_weeks, `staff_id` → staff, `day`, `start`, `end`, `role`. 기존 shifts의 시간·역할 제약을 적용한다. `week` 인덱스. 실제 shifts ID를 외래키로 사용하지 않는다. |
| `weekly_hour_overrides` | `(week, staff_id)` 복합 기본키, `total_minutes`, `desk_minutes`, `opens`, `closes`, `updated_by`, `updated_at`. staff 외래키. |

조정값은 정수로 저장한다. 분은 `0..3900`의 30분 단위이며 `desk_minutes <= total_minutes`, 오픈·마감은 각각 `0..5`이다. 서버에서 검증하고 DB에도 가능한 CHECK를 둔다.

## API 규격

조회는 기존 인증 정책을 적용한다. PUT·DELETE는 기존 `admin(r)` 권한 확인과 CSRF 검증을 적용한다. 잘못된 입력은 기존 오류 형식으로 반환한다.

### GET `/schedule/original?week=2026-10-26`

```json
{
  "week": "2026-10-26",
  "saved": true,
  "staff": [{ "id": 1, "name": "홍길동", "phone": "", "active": 1 }],
  "shifts": [{ "id": 101, "staff_id": 1, "day": "2026-10-26", "start": 540, "end": 600, "role": "desk" }]
}
```

아직 저장하지 않은 주도 HTTP 200으로 `saved: false`, `shifts: []`, 현재 근무자 목록을 반환한다. 실제 shifts 데이터를 원본으로 자동 대체하지 않는다. 역사 조회에 필요한 비활성 근무자도 목록에 포함한다.

### PUT `/schedule/original`

```json
{
  "week": "2026-10-26",
  "shifts": [{ "id": 5, "staff_id": 1, "day": "2026-10-26", "start": 540, "end": 600, "role": "desk" }]
}
```

프론트에서 선택한 주의 실제 근무표를 보내며, 관리자가 확인한 뒤 호출한다. 전달된 `id`는 실제 근무 ID이므로 원본 ID로 재사용하지 않는다. 주 헤더와 원본 근무 행을 한 트랜잭션으로 저장·교체한다. 실제 `shifts`, 이슈 연결, 주당 시간 조정값은 변경하지 않는다. 성공 응답은 `{ "ok": true }`이다.

모든 날짜가 해당 주의 월~금인지, 근무자가 존재하는지, 시간이 09:00~22:00 사이의 30분 단위인지, 시작이 종료보다 빠른지, 역할이 `desk`/`general`인지 검증한다. 같은 근무자의 중복 시간도 **원본 입력 목록 내에서** 검사한다. 기존 `shift()`는 실제 shifts와 겹침을 검사하므로 그대로 호출하면 정상적인 원본 저장도 거절된다. 시간·근무자 검증은 재사용하고 겹침 검사는 대상 데이터에 맞춰 분리한다. 일부 행 실패 시 기존 원본을 보존한다.

### GET `/schedule/hours?week=2026-10-26`

```json
{
  "overrides": [{ "staff_id": 1, "total_minutes": 600, "desk_minutes": 300, "opens": 1, "closes": 1 }]
}
```

수동 조정한 근무자만 반환한다. 미조정 주는 HTTP 200, `{ "overrides": [] }`. 기본 수치는 프론트에서 원본으로 계산하므로 모든 사람의 기본값을 복제해 저장하지 않는다.

### PUT `/schedule/hours/1`

```json
{ "week": "2026-10-26", "total_minutes": 600, "desk_minutes": 300, "opens": 1, "closes": 1 }
```

해당 주·근무자의 조정값을 upsert한다. 원본이 저장된 주인지, 원본 응답의 근무자 목록에 포함된 사람인지 확인한다. 위 범위·정수·30분 단위를 검증한다. 성공 응답은 `{ "ok": true }`.

### DELETE `/schedule/hours/1?week=2026-10-26`

조정 행만 삭제해 원본 자동 계산으로 복원한다. 원본과 실제 근무를 건드리지 않는다. 이미 없어도 성공 처리한다. 응답은 `{ "ok": true }`.

## 화면과 계산

- 위: 축소한 실제 주간 근무표 / 근무 변경 이슈.
- 아래: 원본 근무 시간표 / 원본을 기준으로 계산한 주당 근무 시간.
- 관리자는 `현재 근무표를 원본으로 저장`으로 최초 합의본을 저장하고, 의도적으로 교체할 때만 `원본 다시 저장`을 사용한다.
- 원본의 `표 복사`는 시간·월~금 데스크/대기 이름을 TSV로 복사한다. 실제 근무표를 수정하는 API는 호출하지 않는다.
- 주당 시간에서 이름을 누르면 총 시간·데스크 시간·오픈·마감을 조정할 수 있다. 조정한 사람에게는 `조정`을 표시하고 원본 기준 복원을 제공한다.
- 총 시간은 원본의 근무 분 합계, 데스크 시간은 desk 역할의 분 합계이다. 오픈은 09:00에 시작하는 날 수, 마감은 원본의 해당 날짜 최종 종료 시각에 끝나는 날 수다. 기존 계산대로 최종 종료 시각의 최솟값은 21:00이다.

변경한 백엔드를 실행·배포하기 전에는 새 API가 404이므로 원본·주당 시간 섹션에 조회 오류가 표시될 수 있다. 실제 근무표를 원본으로 잘못 보여주는 임시 대체는 하지 않는다. 기존 데이터는 자동으로 합의본이라고 간주하지 않고 관리자가 최초 저장한다.
